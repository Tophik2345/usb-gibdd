# УСБ ГибДД

Сайт проверки знаний сотрудников: **GitHub Pages + Supabase**.
Регистрация и вход — по электронной почте и паролю. Аккаунт ChatGPT не нужен.
Оформление адаптировано по указанному образцу УП-9: тёмный фон со зданием,
полупрозрачные панели, светлые контурные иконки и сине-серые акценты.

## Что готово

- Каталог опубликованных тестов и учебный пример на шесть вопросов.
- Создание и редактирование своих тестов, черновики, проходной балл.
- Сохранение каждого ответа, продолжение незавершённой попытки.
- Подсчёт баллов в базе и разбор ответов после завершения.
- Личные результаты и результаты участников по тестам автора.
- Вход через Discord после настройки провайдера.
- Автоматическая сборка и публикация через GitHub Actions.

Создавать и редактировать свои тесты могут только владельцы сайта и добавленные ими авторы. Опубликованные
тесты доступны всем участникам сайта; черновики — только автору. Пользователь
видит свои попытки, автор — итоговые оценки участников по своим тестам. Имя
сотрудника вводится самостоятельно, поэтому это не подтверждённая кадровая
идентификация. Можно проходить тест повторно и изучать правильные ответы после
завершения: сайт предназначен для обучения и проверки знаний, а не для
экзамена с защитой от списывания.

## Состояние этого пакета

Код и настройки подготовлены. Реальный проект Supabase и репозиторий GitHub
ещё нужно подключить. В архиве нет рабочих ключей, аккаунтов и данных
сотрудников. Старый сайт и его база автоматически не переносятся.

Проверены TypeScript, production-сборка для вложенного пути GitHub Pages и 11 групп
проверок SQL в настоящем движке PostgreSQL (PGlite). В SQL-проверках подставлены
тестовые JWT claims; это не проверка почтовой доставки, реального OAuth или
входа в облачный Supabase. Внешний браузер не смог открыть локальный
предпросмотр, поэтому опубликованную вёрстку нужно проверить после запуска.

## 1. Создать базу в Supabase

Создайте отдельный проект на бесплатном плане. В SQL Editor выполните **один
раз**, в указанном порядке:

1. `supabase/migrations/202609290001_knowledge.sql`
2. `supabase/migrations/202609290002_demo.sql`

Первая миграция создаёт приватные таблицы и функцию
`public.knowledge_workspace`. Вторая добавляет учебный тест. Успешные миграции
повторно запускать не нужно. Для последующих обновлений добавляйте новые
миграции; не пересоздавайте таблицы с результатами.

Не добавляйте схему `knowledge_private` в список exposed schemas и не выдавайте
пользователям прямой доступ к её таблицам. Публичной должна оставаться схема
`public`, содержащая RPC. Таблицы имеют RLS; RPC проверяет `auth.uid()` и права
на каждую операцию. Верные ответы не отправляются участнику до сдачи попытки.
Оценка рассчитывается по сохранённой версии вопросов, даже если автор позже
изменит тест.

Скопируйте Project URL и **publishable key** из настроек проекта. Разрешён
также старый ключ `anon`. Они предназначены для браузера. `service_role`,
`sb_secret_…`, пароль базы и Discord Client Secret в этот проект не добавляйте.
Сборка отклоняет ключи, не похожие на publishable/anon.

## 2. Настроить вход по почте

В Authentication включите Email и разрешите регистрацию пользователей.
Установите минимальную длину пароля **6 символов** и длину почтового OTP **6 цифр**
на стороне Supabase (Authentication → Sign In / Providers → Email).
Это соответствует `password_min_length=6` и `mailer_otp_length=6`.
Формы продолжают принимать ранее выпущенные коды длиной до 10 цифр;
для новых писем Supabase генерирует шестизначный код.

В URL Configuration укажите полный будущий адрес сайта, например:

```text
https://tophik2345.github.io/usb-gibdd/
```

Замените имя пользователя и название репозитория. Установите этот адрес как
**Site URL** и добавьте его в **Redirect URLs**, включая завершающий `/`.
Для локальной разработки можно отдельно добавить `http://localhost:5173/`.
Приложение возвращает пользователя в корень своего каталога, поэтому отдельный
серверный маршрут `/auth/callback` не требуется.

Для регистрации с подтверждением почты настройте **Custom SMTP** в Supabase.
Встроенная отправка предназначена для тестов и ограничивает получателей
адресами команды проекта; её недостаточно для открытой регистрации сотрудников.
Пароль SMTP храните только в настройках Supabase. Приложение показывает
уведомление о письме и обрабатывает подтверждение при возвращении на сайт.
Откройте ссылку подтверждения в том же браузере, где начали регистрацию:
используется PKCE.

Если письмо содержит цифровой код, после регистрации введите его в форме
«Подтвердите почту». Кнопка **«Отправить код повторно»** запрашивает новое
подтверждение для той же почты через Supabase Auth. Для ранее начатой регистрации
откройте вкладку «Создать аккаунт» и выберите **«Уже получали код? Подтвердить
почту»**: повторно вводить логин и пароль не нужно. Используйте код из последнего
письма. Ограничения частоты отправки и ошибки SMTP обрабатываются отдельно;
подтверждённый аккаунт нужно открывать через вход. Шаблон письма с цифровым кодом
должен содержать `{{ .Token }}` в настройках Supabase; приложение не меняет шаблон.

Если Google SMTP возвращает `535 5.7.8 Username and Password not accepted`,
проверьте SMTP Username и обновите SMTP Password в настройках Supabase:
для Gmail нужен пароль приложения соответствующего Google-аккаунта.
Письмо при такой ошибке не отправляется, а регистрация откатывается.
Проверяйте Auth Logs; сообщение о сетевой ошибке или занятом логине
не объясняет сбой SMTP. Серверный HTTP 500 теперь отображается отдельно
от ошибок соединения, в том числе когда SDK не передаёт `error.code`.

Код также обрабатывает режим без подтверждения email, если владелец проекта
сам выбирает его в Supabase: аккаунт тогда создаётся сразу, но принадлежность
почтового адреса не проверяется. Этот пакет не меняет данную настройку.

## 3. Опубликовать на GitHub Pages

1. Создайте публичный репозиторий, `usb-gibdd`, с основной
   веткой `main`. Публичный репозиторий нужен для GitHub Pages на GitHub Free.
2. Загрузите **содержимое этой папки** в корень репозитория. Включите скрытую
   папку `.github`, файл `.gitignore` и `pnpm-lock.yaml`. Не загружайте `.env`,
   `node_modules` или локальную папку `dist`.
3. В **Settings → Secrets and variables → Actions → Variables** добавьте:

   | Имя | Значение |
   | --- | --- |
   | `VITE_SUPABASE_URL` | Project URL из Supabase |
   | `VITE_SUPABASE_PUBLISHABLE_KEY` | Publishable key или legacy anon key |
   | `VITE_DISCORD_ENABLED` | `false`, пока Discord не настроен |

4. В **Settings → Pages → Build and deployment → Source** выберите
   **GitHub Actions**.
5. Откройте **Actions → Publish GitHub Pages → Run workflow**. При следующих
   изменениях ветки `main` публикация будет запускаться автоматически.
6. После успешного задания `deploy` откройте адрес из GitHub Pages. Проверьте,
   что этот же адрес указан в Supabase URL Configuration.

Workflow сам определяет путь репозитория. Поддерживаются корень домена
`USERNAME.github.io` и сайт в каталоге `USERNAME.github.io/REPOSITORY/`.
Сборка намеренно завершается ошибкой, если обязательные настройки пустые.

Нельзя просто опубликовать исходный `index.html` через Deploy from a branch:
React/TypeScript сначала собираются Vite. Используйте приложенный workflow.

## 4. Проверить работающий сайт

Для проверки используйте два своих аккаунта с подтверждённой почтой. Владелец
должен добавить первый аккаунт в список авторов. Под ним создайте и опубликуйте
тест, под вторым пройдите его. Обновите страницу
в середине попытки и убедитесь, что ответы сохранились. После сдачи проверьте
личный результат участника и раздел «По моим тестам» у автора. Выйдите из
аккаунта, снова войдите и проверьте сохранность данных.

Откройте сайт на компьютере и телефоне, проверьте форму входа, редактор и
прохождение теста. Для проверки требования «без VPN в РФ» откройте именно
опубликованный адрес с российской сети при выключенном VPN и проверьте также
регистрацию, вход и загрузку тестов из Supabase. Доступность страницы GitHub
Pages сама по себе не подтверждает доступность Supabase. Проверка из российской
сети для этого пакета пока не проведена; постоянная доступность у всех
провайдеров не гарантируется.

## Discord — дополнительно

1. Создайте приложение в Discord Developer Portal.
2. Возьмите Callback URL из Authentication → Sign In / Providers → Discord в
   Supabase и добавьте его в OAuth2 Redirects приложения Discord.
3. Включите провайдера Discord в Supabase и сохраните там Client ID и Client
   Secret. Секрет остаётся в Supabase.
4. Установите переменную GitHub `VITE_DISCORD_ENABLED=true` и запустите workflow.

Пока провайдер не настроен, кнопка Discord отключена. Вход по почте работает
независимо от Discord после настройки Email в Supabase.

## Локальная разработка

Нужны Node.js 22.13+ и pnpm 11.25.0.

```bash
npm install --global pnpm@11.25.0
pnpm install --frozen-lockfile
cp .env.example .env.local
```

Заполните `.env.local` публичными настройками своего проекта, затем:

```bash
pnpm dev
pnpm test:session
pnpm test:confirmation
pnpm test:db
pnpm build
pnpm preview
```

`pnpm test:db` не подключается к рабочей базе: создаёт временный PostgreSQL,
применяет настоящие миграции и проверяет анонимный доступ, RLS, приватность
черновиков и результатов, сохранение ответов, проверку данных и подсчёт баллов.

Основные файлы:

| Файл | Назначение |
| --- | --- |
| `app/auth-screen.tsx` | Регистрация, вход и Discord |
| `app/workspace.tsx` | Каталог, прохождение, редактор, результаты |
| `app/reference-theme.css` | Оформление по образцу |
| `lib/supabase.ts` | Клиент Supabase и параметры авторизации |
| `lib/workspace-api.ts` | Обращение к RPC |
| `supabase/migrations` | Схема базы, права и учебный тест |
| `.github/workflows/pages.yml` | Проверка, сборка и публикация |

## Вход по логину

Регистрация: уникальный логин (2–100 символов), электронная почта, пароль
от 6 символов. Подтверждение почты остаётся обязательным. Вход: логин и пароль.
Регистр букв и повторные пробелы в логине не учитываются. У старых аккаунтов
логином стало имя, указанное при регистрации; пароли и результаты сохранены.

Миграция `20260929153139_username_login.sql` создаёт закрытый реестр логинов
и ограничения попыток входа. Edge Function `username-login` проверяет пароль
через Supabase Auth, возвращая клиенту только сессию. Её `verify_jwt=false`,
поскольку это точка входа до получения JWT; аутентификация реализована в функции.
Разрешение логина в почту доступно только серверной роли. Ключи читаются из
серверного окружения Supabase и не передаются в клиент.

Лимиты: 10 попыток на логин за 15 минут и 120 общих попыток в минуту.
Изменение user_metadata не меняет закреплённый логин. Удаление auth-пользователя
удаляет соответствующую запись логина.

Эмблема: исходный SVG с указанной пользователем страницы Википедии:
https://ru.wikipedia.org/wiki/Файл:Emblem_of_the_traffic_police_of_Russia.svg
Сборка проверяет SHA-256 оригинала и включает изображение в сайт. В браузере
оно загружается с GitHub Pages, без обращения к Википедии.

Проверки `pnpm test:db` включают права доступа, миграцию существующих пользователей,
нормализацию и уникальность логинов, ограничения попыток и обработчик входа.
Проверки Auth в обработчике используют контролируемые ответы сервера.

## Разделы сайта

Общая шапка содержит: «Главная», «Тест», «Законы РО», «Для новых сотрудников»,
«Обязанности сотрудников УСБ», «Полезные ссылки». На узком экране навигация
открывается кнопкой меню. Разделы имеют адреса с якорем, например `#home` и `#tests`.
Главная содержит ранее утверждённый текст. Тесты, результаты и управление
объединены в разделе «Тест», для работы с ними нужен вход. Публичные
информационные разделы открываются без входа и не содержат данных аккаунтов.
Четыре новых информационных раздела пока содержат только заголовки и отметку
об отсутствии материалов; нормативные тексты и адреса ссылок должны быть
предоставлены владельцем сайта.

## Ограничение создания тестов

Раздел «Тест → Доступ» доступен владельцам сайта. Для выдачи доступа нужно
указать точный логин зарегистрированного сотрудника и нажать «Добавить автора».
Почта сотрудника должна быть подтверждена. Кнопка «Убрать доступ» отзывает
создание и редактирование тестов; аккаунт, тесты и результаты остаются.

Роли хранятся в закрытой таблице `knowledge_private.test_creators` и проверяются
при каждом запросе. Регистрация, отображаемое имя, данные запроса и JWT metadata
не дают прав автора или владельца. Владелец может управлять списком авторов;
автор создаёт и редактирует только свои тесты. Права просмотра чужих результатов
не расширяются: итоговые оценки видны автору соответствующего теста.

Первоначальные владельцы назначаются отдельно администратором проекта после
явного указания аккаунтов пользователем. Миграция не угадывает владельца по
имени, порядку регистрации или адресу почты. Владельцев нельзя удалить из списка
через интерфейс авторов, и автор не может передавать права другим людям.

Миграция `20260929160954_test_creator_access.sql` закрывает прямой вызов прежней
внутренней функции и оставляет единственный публичный RPC с серверной проверкой
прав. Локальные проверки включают запрет самоавторизации, выдачу и отзыв доступа,
сохранность тестов после отзыва, подтверждение почты и работу нескольких владельцев.

## Личный профиль

Логин в шапке открывает `#profile`: имя пользователя, личная электронная почта,
уровень доступа, количество завершённых попыток и средний результат. Из профиля
можно открыть свои результаты и тесты; владельцам также доступен переход к
управлению авторами. Без входа адрес профиля открывает форму авторизации.

Роль «Заместитель» (`deputy`) разрешает создавать и редактировать только свои тесты.
Просмотр списка авторов, выдача и отзыв доступа разрешены только владельцу.
Роль возвращается сервером и отображается в личном профиле и списке авторов.

### Мои задачи

В личном профиле блок «Мои задачи» собирает задания с ближайшими сроками,
незавершённые тесты и тренировки, состояние личного допуска и последние
обращения сотрудника. Задания сортируются по сроку; просроченные отмечаются
отдельно. Из карточки можно начать назначение или продолжить сохранённую
попытку. Отменённые и обнулённые назначения и их незавершённые попытки
не предлагаются для продолжения; история остаётся в результатах.

Показываются три ближайших задания и три незавершённые попытки. Остальные
задания открываются во вкладке «Мои задания», остальные попытки — кнопкой
«Все незавершённые тесты». По обращениям показаны три последних из первой
страницы личной очереди; ссылка «Все мои обращения» открывает полный список
с постраничным просмотром. У рассмотренных и отклонённых обращений доступен
переход к ответу. Личная очередь сохраняется при переходах даже у руководителя.

Допуск показывает прогресс по материалам и обязательным тестам, решение и
комментарий руководителя. При готовой программе предлагается открыть
подготовку и подать заявку. Ошибка загрузки допуска или обращений отображается
в соответствующей карточке с отдельной кнопкой повтора. «Обновить задачи»
перечитывает задания, попытки, допуск и обращения. Сроки отображаются по МСК.
Смена аккаунта сбрасывает весь блок и отменяет запросы прежнего пользователя.

## Автосохранение редактора и копирование тестов

В «Тесты → Управление» редактор автоматически сохраняет незавершённые вопросы
примерно через секунду после ввода. Черновики хранятся отдельно от тестов:
правки опубликованного теста применяются только кнопкой «Сохранить тест».
Новые тесты и копии по умолчанию закрыты для прохождения.

При сбое связи правки остаются в браузере текущего аккаунта и отправляются
повторно при восстановлении соединения. После закрытия редактора или перезагрузки
их можно открыть в «Черновики редактора → Продолжить». Локальное восстановление
требует того же браузера и сохранённых данных сайта; синхронизированные черновики
доступны и на другом устройстве. Ошибки сохранения отображаются в редакторе.

При одновременной работе из разных вкладок или устройств устаревший черновик
не перезаписывает новую версию. Можно сохранить свои правки отдельным черновиком
или явно загрузить сохранённую версию. Удаление черновика требует подтверждения
и не удаляет исходный тест.

«Копировать» создаёт независимый закрытый тест с новыми ID теста и вопросов.
Переносятся вопросы, правильные ответы, пояснения, тема, проходной балл,
перемешивание и время прохождения. Попытки, результаты и назначения принадлежат
исходному тесту и в копию не переносятся. Копировать можно только свои тесты.

Миграция `20261001130000_editor_drafts.sql` добавляет закрытую таблицу черновиков
и RPC `knowledge_editor`. Все операции требуют действующего подтверждённого
аккаунта и актуальных прав автора. Версии черновика и исходного теста проверяются
на сервере; публикация и удаление соответствующего черновика выполняются
атомарно. `pnpm test:drafts` проверяет сохранение, восстановление, конфликты
и сетевые ошибки; `pnpm test:db` проверяет права и операции на PostgreSQL (PGlite).

# Назначения и работа над ошибками

В разделе «Тест → Задания» сотрудник видит свои назначения. Автор может
назначить свой опубликованный тест зарегистрированному пользователю с
подтверждённой почтой, указав его логин и срок сдачи. Даты вводятся и показываются
по московскому времени — МСК (UTC+3), независимо от часового пояса устройства.
В базу передаётся абсолютный момент в UTC; ранее сохранённые сроки не сдвигаются.
Единые преобразования находятся в `lib/date-time.ts`; `pnpm test:time` проверяет
ввод и показ дат из разных часовых поясов, смену суток и несуществующие даты.

Назначение сохраняет вопросы и проходной балл на момент выдачи. Изменение или
снятие исходного теста с публикации не меняет уже назначенную проверку. Задание
получает статус «Пройден» только после достижения проходного балла в попытке,
начатой из задания. Предыдущие проверки и тренировки его не закрывают. После
срока можно продолжить сдачу; дата успешной сдачи и опоздание сохраняются.
Автор может изменить срок или отменить своё незавершённое назначение.
Результаты отменённых назначений сохраняются; отмена не требует сдачи.

В разборе завершённой попытки кнопка «Работа над ошибками» создаёт отдельную
тренировку только по неверным ответам из сохранённой версии вопросов.
Тренировки доступны самому сотруднику, не меняют исходную оценку, не входят в
средний результат проверок и не засчитываются как выполнение назначения.
Незавершённую тренировку можно продолжить. История находится во вкладке
«Результаты → Тренировки».

В «Тесты → Результаты» можно отобрать завершённые попытки по тесту, имени
сотрудника, датам, проценту верных ответов и статусу. Даты включают весь
выбранный день по МСК. Кнопка «Применить» обновляет список; «Сбросить» очищает
фильтры. Личные проверки, тренировки и результаты по своим тестам доступны
в отдельных вкладках.

«Скачать CSV для Excel» выгружает все найденные результаты, включая записи
за пределами первой страницы и прежнего лимита 500. CSV использует UTF-8 с BOM,
разделитель `;` и московское время. Выгрузка учитывает применённые фильтры;
при ошибке или отмене неполный файл не скачивается. Имена и названия,
похожие на формулы Excel, экранируются.

Миграция `20261001120000_results_export.sql` добавляет RPC `knowledge_results`

Миграция `20260929200858_learning_assignments.sql` добавляет закрытую таблицу

## Восстановление пароля и управление аккаунтами

На странице входа кнопка **«Забыли пароль?»** запрашивает письмо восстановления
по почте аккаунта. Код подтверждается отдельно от регистрации; после подтверждения
нужно ввести новый пароль дважды (6–128 символов). Переход по ссылке восстановления
также открывает смену пароля. Новый пароль и цифровые коды не сохраняются в браузере.
В Authentication → Emails → Reset password установите содержимое
`supabase/templates/recovery.html` и тему «Восстановление пароля — УСБ ГибДД».
Шаблон регистрации и SMTP менять не требуется.

После успешного запроса письма кнопка повторной отправки показывает 60 секунд
ожидания. Таймер привязан к почте и типу письма, сохраняется при обновлении вкладки;
окончание таймера не отменяет дополнительные ограничения Supabase.

Для существующей базы с предыдущими миграциями выполните **один раз** только
`supabase/migrations/20261001110000_account_management.sql`. Она добавляет серверные
проверки и RPC; установка не блокирует и не удаляет аккаунты. Схема
`knowledge_private` остаётся закрытой для Data API. Владельцу на вкладке
**Тесты → Доступ** доступны поиск аккаунтов, блокировка, разблокировка и удаление
с отдельным подтверждением. Сервер проверяет роль из таблицы авторов, а не из
редактируемых metadata или параметров браузера. Свой аккаунт, владельцев и
заместителей блокировать и удалять нельзя. Аккаунты с авторскими тестами или
Storage-файлами защищены от удаления; для них используйте блокировку.

Блокировка сохраняет результаты, отзывает Auth-сессии и запрещает все личные RPC
даже со старым JWT. Разблокированный сотрудник входит заново. Удаление каскадно
удаляет личные данные целевого аккаунта и необратимо; чужие тесты сохраняются.
Действия записываются в журнал управления. Серверные ключи в клиенте не нужны.
Публичная проверка занятого логина возвращает только признак доступности и имеет
собственное ограничение частоты; email и UUID по логину она не выдаёт.

Проверки: `pnpm test:recovery`, `pnpm test:confirmation`, `pnpm test:session`,
`pnpm test:db`, `pnpm build`. SQL выполняется в PostgreSQL/PGlite с локальными
Auth claims; доставка письма и работа нового пароля проверяются отдельно
в настоящем аккаунте.

Миграция `20261001150000_rank_test_permissions.sql` переводит права на тесты
с прежней роли автора на текущее звание сотрудника действующего состава:

- **Капитан и выше**: результаты и назначения всех сотрудников, назначение
  любого опубликованного теста, изменение срока, отмена и обнуление назначения.
- **Полковник и выше**: создание, копирование и редактирование тестов всех
  авторов, включая их неопубликованные тесты. Авторство исходного теста сохраняется.
- **Ниже капитана**: собственные задания, попытки и результаты. Роль автора
  или владельца не обходит установленный порог звания.

В разделе **Тесты → Задания → Все сотрудники** действие **Обнулить назначение**
создаёт новое задание с новым сроком и актуальной опубликованной версией теста.
Прежнее назначение помечается как обнулённое. Все его попытки, ответы, оценки,
временные отметки и прежний зачёт сохраняются. Незавершённая прежняя попытка
доступна для просмотра; прохождение продолжается в отдельной новой попытке.
Ни одна попытка не удаляется и не перезаписывается при обнулении.

**Тесты → Результаты → Все сотрудники** содержит фильтры, разбор сохранённых
ответов и экспорт всей выбранной истории в CSV. Просмотр чужой попытки не
позволяет отвечать или завершать тест за сотрудника. **Тесты → Управление**
доступно от полковника; черновики каждого редактора остаются личными.

Каждый серверный запрос проверяет подтверждённый, незаблокированный аккаунт,
действующий состав и текущее звание. Архивирование, блокировка или понижение
закрывают доступ. Версии назначений и тестов защищают от устаревших форм,
одновременных обнулений и конфликтующих правок. Обнуление записывается в журнал.
Права владельца на аккаунты и служебные роли остаются отдельными.

`pnpm test:db` проверяет прежний контракт до этой миграции и новый контракт
после её применения, включая все 16 порогов звания, чужие тесты, закрытые
черновики, сохранность завершённых и незавершённых попыток, ошибки и конфликты.

## Личные уведомления

После входа колокольчик в шапке показывает число непрочитанных уведомлений:
новое или изменённое назначение, срок в ближайшие 24 часа, просрочка,
ответ на собственное обращение и решение по допуску. Нажатие открывает
нужное назначение, обращение или вкладку допуска. Можно отметить отдельное
уведомление прочитанным или прочитать сразу все, включая следующие страницы.
Прочтение сохраняется в аккаунте при обновлении страницы и на другом устройстве.

Миграция `20261002000100_notifications.sql` создаёт закрытую таблицу отметок
и RPC `knowledge_notifications`. Лента строится из текущих личных записей:
выполненные, отменённые и обнулённые назначения исчезают; новый срок или ответ
получает новое уведомление. Изменение программы может потребовать подтвердить
допуск заново. Приложение обновляет счётчик раз в минуту на видимой странице,
при возвращении в окно и при открытии ленты. Доступны ручное обновление
и повторная загрузка после ошибки.

RPC принимает только подтверждённый, незаблокированный аккаунт и определяет
пользователя по сессии. Чужие уведомления и прямой доступ к отметкам закрыты.
Лента не содержит вопросов или ответов теста. `pnpm test:db` проверяет права,
сохранение прочтения, сроки, обновления, смену часового пояса и пагинацию;
`pnpm test:session` проверяет отбрасывание ответов прежнего аккаунта.

## Сводка руководителя

В **Тесты → Сводка** собраны активные и просроченные назначения, сроки в ближайшие
24 часа, последние результаты и заявки на допуск. Ссылка на сводку есть в личном
профиле. Результаты можно смотреть за 7, 30 или 90 календарных дней по МСК;
период включает текущий день. Статистика учитывает все завершённые проверки,
включая повторные попытки, и исключает тренировки и демонстрационный тест.
Средний результат — среднее процентов отдельных проверок, доля с зачётом —
доля проверок, достигших сохранённого проходного балла.

Счётчики считаются в базе по всем записям; в каждой очереди показываются первые
8. Завершённые, отменённые и обнулённые назначения не входят в активную очередь.
Актуальные заявки на допуск показываются только для подтверждённых,
незаблокированных сотрудников действующего состава. Заявки по устаревшей
программе исключаются до повторной подачи. Кнопка **Обновить сводку** загружает
текущее состояние; открытие сводки и смена периода также запускают загрузку.

Миграция `20261002010000_leader_dashboard.sql` добавляет RPC `knowledge_dashboard`.
Тесты и назначения доступны от звания **Капитан**; допуски — только владельцу и
заместителю. Эти права проверяются отдельно при каждом запросе и точечном
переходе. Владельцу со званием ниже капитана доступна очередь допуска.
Сводка не меняет назначения, попытки и решения. Переходы открывают существующие
формы управления, в том числе записи за пределами первоначально загруженного
списка. `pnpm test:db` проверяет права, расчёты, периоды, исключённые записи,
приватность ответов и смену часового пояса.

## Общий поиск, календарь, история и печать

Лупа в шапке открывает **Поиск по сайту** (`#search`). Гостям доступны статьи
восьми документов и публичные памятки; после входа добавляются опубликованные
тесты и материалы подготовки. Все слова запроса должны совпасть; учитываются
е/ё и распространённые русские окончания. Поиск по номеру статьи ведёт к
конкретной норме. Ответы, пояснения к вопросам и черновики тестов в поиск не
попадают. Перед открытием теста публикация проверяется заново; действующее
личное назначение открывается вместо свободного прохождения. Тест запускается
только отдельной кнопкой пользователя. Серверные результаты выдаются страницами
по 20 с точным общим количеством, законы — с кнопкой дополнительных статей.

В профиле есть **Календарь сроков** (`#calendar`) и **Моя история** (`#history`).
Календарь показывает только личные активные задания, группирует сроки по МСК
независимо от часового пояса устройства и позволяет перейти к самому раннему
просроченному сроку. Обновление загружает текущее состояние назначений.
История объединяет завершённые проверки, повышения и сохранённые решения
по допуску. Обнуление назначения не удаляет результаты. Тренировки, учебный
пример и незавершённые попытки исключены; оценка берётся из сохранённой попытки.
Историческое решение по допуску не заменяет его текущий статус.

Ссылка **История сотрудника** в составе и служебном профиле открывает историю
выбранного сотрудника. От капитана доступны чужие результаты и повышения,
владельцу и заместителю — чужие решения по допуску. Права проверяются отдельно
в каждом запросе; владелец со званием ниже капитана не получает чужие результаты.
История архивного сотрудника сохраняется. Страницы истории используют курсор
и время снимка, чтобы новые события не сдвигали уже просмотренные записи.

**Тесты → Сводка → Печать / PDF** открывает стандартное окно печати. Для файла
выберите «Сохранить как PDF». Отчёт содержит время формирования, выбранный
период, точные счётчики и показанные строки очередей с их количеством; в него
попадают только доступные пользователю разделы. Печать не меняет данные.

Миграция `20261002020000_search_history.sql` добавляет закрытый вспомогательный
метод истории, индекс событий и RPC `knowledge_search` / `knowledge_history`,
доступные только подтверждённым, незаблокированным аккаунтам. Новые запросы
не меняют назначения, результаты, решения или журнал действий. Прямой доступ
к таблицам и вспомогательному методу закрыт. `pnpm test:db` проверяет фильтрацию,
права, страницы и отсутствие ответов в выдаче; проверки дат покрывают календарь
и границы месяцев при четырёх часовых поясах устройства.
